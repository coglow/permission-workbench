# 权限管理工作台

基于 React、TypeScript、Express 和 SQLite 的权限管理项目，以项目管理为业务场景，串联角色授权、数据范围、动态菜单与后端接口校验。

管理员可以配置角色、分配用户角色、调整菜单，并通过审计日志查看配置变更；业务用户按照自己的有效权限查看、创建和编辑项目。

在线体验：[https://stars.coglow.top](https://stars.coglow.top)

## 核心功能

| 功能           | 说明                                                               |
| -------------- | ------------------------------------------------------------------ |
| 项目管理       | 查看项目列表与详情，创建项目，编辑名称、状态和描述                 |
| 角色配置       | 创建和编辑角色，配置操作权限与数据范围，启用或停用角色             |
| 用户角色分配   | 为用户分配多个角色，查看合并后的有效权限                           |
| 数据范围       | 按本人、所在团队及下级团队、全部三个范围控制项目数据访问           |
| 动态菜单与路由 | 配置菜单名称、层级、排序和启停，绑定已经实现的页面                 |
| 项目报表       | 按独立的报表权限与数据范围，统计项目总数和各状态数量               |
| 审计日志       | 记录角色、用户角色分配和菜单配置的变更，展示操作者、时间及变更摘要 |

## 快速启动

环境要求：Node.js 22.18 或更高版本、pnpm 11。项目通过 `packageManager` 指定 pnpm 11.22.0。

在项目根目录执行：

```sh
pnpm install
pnpm db:init
pnpm dev
```

`pnpm db:init` 会删除已有数据库，再创建表结构并写入预置账号、角色、菜单和项目数据。首次启动时执行；后续恢复初始数据也使用此命令。

启动后访问：

- 前端：[http://127.0.0.1:5173](http://127.0.0.1:5173)
- API 健康检查：[http://127.0.0.1:3001/api/health](http://127.0.0.1:3001/api/health)

`pnpm dev` 同时启动前端和 API，Vite 将 `/api` 请求代理到 `http://127.0.0.1:3001`。SQLite 文件默认保存在 `data/permission-workbench.sqlite`，可通过环境变量 `DATABASE_PATH` 指定其他文件路径。

## 关键设计

### 角色、操作权限与数据范围

授权关系为：**用户 → 角色 → 操作权限及其数据范围**。

权限点由 `shared/catalog.ts` 统一定义，例如 `project.record.view`、`project.record.edit` 和 `project.report.view`；后台为角色配置这些权限的授权关系。

| 数据范围             | 判定方式                                       |
| -------------------- | ---------------------------------------------- |
| 本人（`self`）       | 项目负责人是当前用户                           |
| 团队及下级（`team`） | 项目所属团队位于当前用户所在团队及其下级团队中 |
| 全部（`all`）        | 全部项目                                       |

新建项目的负责人和所属团队由服务端根据当前用户写入，后续编辑保持这两个字段不变。多角色按权限码合并，同一操作的数据范围取最宽的一档：`all > team > self`。角色停用后，其分配关系与授权配置保留，重新启用后继续生效。

查看和编辑分别配置数据范围，编辑范围须包含在查看范围内。例如，可以允许用户查看团队项目，同时只编辑本人负责的项目。详情接口返回记录级的 `canEdit`，页面据此展示编辑入口。

### 页面访问与接口授权

前端依据权限展示导航、操作按钮及页面访问状态；后端在每次受保护请求中读取当前身份与有效授权，独立校验操作权限和数据范围。

- **列表与报表**：将数据范围转换为 SQL 条件，在查询或统计时过滤数据。
- **详情与编辑**：依次校验身份、操作权限、记录是否存在以及目标记录的数据范围。
- **会话**：使用 HttpOnly Cookie 保存会话令牌，数据库保存令牌摘要与过期时间。

项目报表使用独立的 `project.report.view` 权限，数据范围也独立配置。

### 菜单配置与路由生成

页面组件、标准路径和所需权限在页面登记表中固定绑定。菜单配置负责组织入口，服务端分别返回启用的页面路由和当前用户可见的导航树。

| 页面状态                               | 访问结果                        |
| -------------------------------------- | ------------------------------- |
| 页面菜单及其上级均启用，用户有权限     | 展示菜单并允许访问              |
| 页面菜单及其上级均启用，用户无权限     | 隐藏菜单，直接访问显示 403 页面 |
| 页面未配置菜单，或菜单、上级目录已停用 | 直接访问显示 404 页面           |

项目详情与编辑使用固定路由，按操作权限和记录的数据范围判断访问资格。菜单停用影响对应的配置页面路由，接口授权仍由各自的权限规则决定。

后端在下一次受保护请求中应用最新授权。前端在页面导航、标签页重新可见或业务请求返回 403 时，重新获取身份、权限与导航配置，并在有效授权变化后重新加载业务数据。

### 配置变更与审计

角色配置、用户角色分配和菜单配置均与审计日志在同一数据库事务内写入，保证变更与日志一起提交。审计摘要记录权限增减、数据范围调整和菜单字段变化。

内置管理员角色保持只读，预置管理员账号保留管理员角色，系统管理目录及其四个管理菜单保持固定，确保始终能够通过管理页面调整配置。

## 技术栈与目录

- **前端**：React、TypeScript、Vite、React Router、Ant Design。
- **后端**：Node.js、TypeScript、Express。
- **数据存储**：SQLite、better-sqlite3。

```text
web/src/
  pages/          页面与业务交互
  components/     表单、编辑器与状态组件
  router.tsx      路由与身份加载
  identity.tsx    身份、权限读取与认证守卫
  layout.tsx      导航与布局
server/src/
  db/             表结构、初始化与种子数据
  auth.ts         登录、会话与有效权限计算
  access.ts       权限守卫与数据范围判定
  projects.ts     项目列表、详情、创建与编辑
  reports.ts      项目统计
  roles.ts        角色配置
  users.ts        用户角色分配
  menus.ts        菜单配置与导航生成
  audit.ts        审计记录
shared/
  catalog.ts      权限点、数据范围与页面登记表
  contracts.ts    前后端共享的数据契约
```
